# Left Messages

Elyx-плагин для exteraGram от **@swagnonher**: **ваши исходящие сообщения отображаются в левой
части чата — как сообщения собеседника** (в стиле Telegram Desktop), при этом пузырь остаётся
**вашем цвете**. Полностью нативное отображение; аватарки и имена показываются ровно там, где они
показываются для собеседника (в группах, форумах и т.д. — в том числе для своих сообщений).

Собранный плагин: `builds/LeftMessages-1.0.elyx` (и `.eaf` — формат тот же, другое расширение).

## Умная ниточка

Вся визуальная логика «своё/чужое» в Telegram Android держится на одном флаге:

```
org.telegram.messenger.MessageObject.isOutOwner()
```

`ChatMessageCell` вызывает его ~300 раз (сторона пузыря, цвета, радиусы, раскладка текста и
медиа, реакции, реплаи, стиль времени/галочек), а размещение ячейки в списке тоже зависит от
него. Плагин «врёт» этому методу (`false`) только для исходящих сообщений, привязанных к ячейкам
чата — и всё отрисовывается **нативно**, как входящее.

## Склейка пузырей (v1.1.0)

Флаги «приклеено к предыдущему/следующему сообщению» вычисляются в
`ChatActivity$ChatActivityAdapter.onBindViewHolder` сравнением `isOutOwner()` двух соседей.
Во время бинда текущее сообщение ещё не привязано к ячейке (реальное значение), а сосед уже
привязан (ложь) — сравнение ломалось: свои сообщения не склеивались со своими, а иногда
склеивались с чужими.

Решение: на время `onBindViewHolder` ложь **приостанавливается** (флаги считаются по реальным
статусам: свои ↔ свои склеиваются, свои ↔ чужие нет), а внутри вложенного `setMessageObject`
ложь снова активируется, чтобы ячейка разложила себя «по-входящему». Восстановление — с
самолечением от протечек счётчика.

## Свой цвет пузыря (v1.1.0)

- `ChatMessageCell.getThemedColor(int)`: все ключи `key_chat_in*`, у которых есть парный
  `key_chat_out*` (таблица строится рефлексией из полей `Theme`), подменяются на out-варианты
  → текст, время, ссылки, лоадеры, сикбары, реакции и т.д. — в «своём» цвете.
- Фон пузыря: цвет запекается в `MessageDrawable.setTop(...)`. На время этих вызовов для
  «перевёрнутых» сообщений выставляется официальный `MessageDrawable.overrideColor`
  (= `Theme.key_chat_outBubble` / `key_chat_outBubbleSelected`), затем значение восстанавливается —
  общий инстанс drawable остаётся безопасным для сообщений собеседника. Геометрия при этом
  остаётся входящей (скругления/хвостик слева), цвет — исходящий.

## Почему всё остальное не ломается

| Механика | Почему работает |
| --- | --- |
| Открытие медиа (PhotoViewer, видео, голосовые, скачивание) | не зависит от `isOutOwner()` |
| Альбомы/галереи | сетка альбома считается в `MessageObject$GroupedMessages.calculate()` **до** привязки ячеек и по реальному `out` («правая» сетка); хук на `calculate()` на время расчёта помечает сообщения группы как «рендерящиеся», поэтому сетка строится под ту же сторону, под которую ячейки и рисуют |
| Прогресс отправки/загрузки медиа | зависит от `MessageObject.isOut()` — **он не хукается** |
| Уведомления, звонки, отправка | обрабатывают свежие, ещё не привязанные объекты; ложь ограничена привязанными к ячейкам сообщениями (+ временное помечение на время `calculate()`) |
| Аватарки/имена | не подавляются — входящая раскладка сама показывает их там, где положено, в том числе для своих сообщений |
| Переключение «на лету» | повторный бинд привязанных ячеек (`setMessageObject` re-invoke) — чат обновляется сразу |

## Настройки

- **Мои сообщения слева** — главный переключатель (по умолчанию включён).
- **Свой цвет пузыря** — перевёрнутые сообщения остаются в исходящем цвете (по умолчанию включено).
- **Также в Избранном** — применять флип и в «Saved Messages» (по умолчанию включено).

## Известные особенности (по дизайну)

- Галочки «прочитано» на своих сообщениях отображаются в стиле входящих (сообщение выглядит
  как сообщение собеседника).
- Пункт «Редактировать» может не отображаться в контекстном меню своих сообщений — приложение
  считает сообщение чужим.
- Цвета реакций-пилюль внутри перевёрнутых сообщений могут остаться входящими (они резолвятся
  вне `ChatMessageCell.getThemedColor`).

## Совместимость

- app: exteraGram >= 12.5.1, sdk >= 1.4.3.8 (проверено `mandochka_check` для 1.4.3.8–1.4.3.10).
- Хуки завязаны на имена методов/полей (`isOutOwner`, `needDrawAvatar`, `setMessageObject`,
  `onBindViewHolder`, `setTop`, `getThemedColor`, `drawNameAvatar`, `overrideColor`), не на
  сигнатуры — устойчиво к минорным изменениям клиента.

## Сборка

Требуется Mandochka (MCP-инструменты `mandochka_*`):

```
mandochka_check  (проверка SDK-совместимости)
mandochka_build  (check_ast=true)
```

Стабы для компиляции Java-моста — `compile_stubs/stubs.jar` (базовые стабы Xposed/Android +
`android.os.Handler/Looper`).
